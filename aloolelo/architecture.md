# Architecture Context (`architecture.md`)


## Stack

| Layer | Technology | Role |
| :--- | :--- | :--- |
| Framework | Next.js 14+ (App Router) + TypeScript | Full-stack framework, SSR, Server Components, and API routes |
| UI & Styling | Tailwind CSS + shadcn/ui + Lucide Icons | Responsive layout, design system components, and dashboard UI |
| Multi-Agent | LangChain / LangGraph (TypeScript) | Multi-agent state orchestration, dynamic routing, and tool execution |
| Auth | Clerk | Multi-tenant user authentication, RBAC, and session management |
| Database | Prisma ORM + PostgreSQL (Supabase) | Relational HR data storage, review mappings, and system metadata |
| Vector Search | Pgvector (via Supabase) | Native vector embeddings for semantic search over notes and feedback |
| Audit & Privacy | Custom AES-256 Crypto + Winston / Logflare | Field-level PII encryption at rest and append-only audit logging |


## System Boundaries

- `app/` – Next.js App Router housing page views, UI dashboards, and backend API routes
- `components/` – Reusable UI components powered by shadcn/ui and custom design patterns
- `lib/` – Shared server utilities, crypto encryption handlers, Logger setups, and Prisma DB instances
- `agents/` – LangGraph multi-agent graph declarations, state definitions, and LLM tool chains
- `prisma/` – Database schema definitions, vector extension configuration, and migration history
- `public/` – Static assets, images, branding elements, and public fonts

## Storage Model

- **Relational Database (PostgreSQL / Prisma)**:
  - User profiles, roles (Employee, Manager, HR Admin, Reviewer), organizational hierarchy.
  - 360° inputs (self-assessments, manager feedback, peer feedback, project goals).
  - Generated review reports, section states, human override history, and status flags.
  - Append-only audit logs (capturing all agent runs, bias flags, and reviewer approvals).
- **Vector Database (Pgvector)**:
  - Document embeddings for ungrounded text sources (raw meeting notes, peer feedback, project outcomes) used during evidence retrieval.
- **Encrypted Document Store / File Storage (AWS S3 or Supabase Storage)**:
  - Raw uploaded documents (PDFs, raw meeting transcripts) stored with tenant-isolated KMS encryption.

## Auth and Access Model

- **Authentication**: Every user signs in via Clerk. User identity is mapped to an internal `User` record via webhooks.
- **Role-Based Access Control (RBAC)**:
  - *Employee*: Can view/submit their own self-assessments and finalized reviews.
  - *Manager / Peer*: Can submit feedback for assigned review cycles.
  - *HR Reviewer / Admin*: Accesses the HITL dashboard, triggers agent workflows, overrides agent findings, and approves final report release.
- **Data Isolation**: Review data, feedback, and generated reports are strictly scoped to the employee, their assigned reviewer, and HR admins. Multi-tenant row-level security prevents unauthorized cross-department data exposure.

## Invariants

1. **No Unapproved Report Release**: Synthesised performance reports must never be accessible to the subject employee until explicit Human-in-the-Loop (HITL) approval is logged.
2. **Strict Evidence Grounding**: Every summary statement or rating generated by the Synthesizer agent must cite at least one explicit source ID (feedback entry, project outcome, or meeting note). Ungrounded claims must be flagged by the Auditor agent.
3. **PII & Sensitivity Protection**: Raw performance data must pass through the privacy sanitizer (`lib/privacy/`) before being transmitted to third-party LLM providers.
4. **Immutable Audit Trail**: All agent outputs, bias detection flags, and human overrides must be recorded in an append-only audit trail for governance compliance.
5. **Non-Blocking Ingestion**: Data collection and agent orchestration workflows must run asynchronously via background jobs or event streams (never blocking synchronous HTTP request/response loops).
